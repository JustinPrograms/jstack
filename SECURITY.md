# Security Policy

## Supported versions

Security fixes are made on the latest version of JStack. Older revisions may not receive separate patches, so users should update before reporting behavior that has already been fixed on `main`.

## Reporting a vulnerability

Do not disclose a suspected vulnerability in a public issue, pull request, discussion, fixture, or test log.

If the repository offers a **Report a vulnerability** button on its Security page, use it to submit a private report. Otherwise, open a public issue titled `Security contact request` without technical details, reproduction steps, or sensitive data. The maintainer will arrange a private channel for the full report.

Include the affected JStack revision, impacted host, expected and observed behavior, reproduction conditions, and potential impact. Use synthetic data and remove credentials or private repository content.

You should receive an acknowledgement within seven days. Please allow time to investigate and prepare a fix before publishing details.

## Scope

Security reports may cover the shipped skills, setup scripts, repository automation, or behavior that could cause an agent to exceed the authority described by JStack. General bugs and feature requests belong in the public issue templates.
